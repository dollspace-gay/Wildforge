# Discovery and contextual interaction

Catalogue/copying, settled readings, installed apparatus, preparation use,
contextual alchemy selection, waystone sidecars, and sleep voting have separate
adapters. They coordinate the same player-facing entry points with explicit
imports. Physical observations and conserved transactions remain in World;
guests send the existing protocol operation and receive bounded host outcomes.

Preserve selection, settle timers, physical holder identity, writing-surface
adjacency, and callback/toast ordering. Contextual alchemy chooses the requested
operation; its host-owned batch/container/Current state is never duplicated here.
Player waystone knowledge is client sidecar data independent of replica terrain.

Read [AGENTS.md](AGENTS.md). Final checks exercise discovery settle/copy/rejection,
contextual alchemy, player sidecars, sleep votes, and native guest entry/actions.
