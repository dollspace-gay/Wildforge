# Graphical guest adapters

The parent pump takes the Remote lifetime, handles disconnect/timeout, polls and
applies shared replica-domain messages, then routes the remaining protocol replies
through one exhaustive match. RemoteFlow explicitly distinguishes the original
pump-abort paths from continuing to the next message.

Reply families adapt entry/content, terrain, entities, knowledge/magic, player,
containers and presence to presentation. GuestSession remains admission/content/
replication/transport authority; helpers do not recreate that machinery. Per-frame
terrain admission and initial mesh readiness precede interpolation, upstream
movement/view requests and restoring the Remote owner to the application.

An abort drops the taken owner just as the original pump returned before restoring
it. Nested snapshot-loop skips retain their original per-entity behavior. No guest
reply constructs a save-capable World or advances authoritative simulation.

Run applicable UI/session/inventory characterization and parity tests, then the
root Rust gates and final native gameplay/GPU proofs from the repository root.
